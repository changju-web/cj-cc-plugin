# 信号识别与门槛

## 信号口径

只认**生成会话内**的显式信号，台账是唯一输入源：

| 类型 | 判定 | 例 |
| --- | --- | --- |
| 纠偏 | 用户指出产物不对、给出正确改法 | "api 文件名应该是 kebab-case" |
| 主动要求 | 用户提出期望效果（非纠错） | "表单默认两列布局" |
| 要求重生成 | 推翻本次产物要求重来 | "不对，重新生成" |

会话外闲聊、跨会话 diff 考古、推测的隐含偏好——一律不入账。

## 台账条目格式（捕获时写入，一行一条）

```text
- [YYYY-MM-DD] <plugin>:<skill> | <纠偏|要求|重生成> | <用户原话摘录> | <当时的处理> | <涉及产物路径>
```

行尾留给巡检打标：`→ 已蒸馏 YYYY-MM-DD <plugin>@<ver>` 或 `→ 留观 YYYY-MM-DD`。原文永不改写。

## 双写规则（捕获时由生成 skill 执行）

- 主动要求类：项目约定记忆文件（提炼后规则）+ 台账（原话）各一条
- 纠偏类：至少记台账；规则可泛化时同步提炼进项目约定文件

约定记忆文件：`docs/api-spec.md`（model/api 层）、`docs/ui-codegen.md`（UI 生成层，内分共通 / PC / 小程序三节）。

## 归因分层

每条信号先归因再定改动落点：

1. **api-spec 层** — 转换规则问题（类型还原、命名、形态判定、合并策略）
2. **UI 生成层** — 页面 / 组件生成规则问题
3. **装配接缝** — model/api ↔ UI 的引用形态、字段对不上等；先判误差源头在上游还是下游，改产生误差的一层，不把上游误差写成 UI 规则
4. **非生成问题** — 后端、环境、业务决策 → 报告说明，不入行动项

## 升格门槛

| 聚合结果（同插件 + 同规则点） | 处置 |
| --- | --- |
| 复现 ≥2 条（跨项目或同项目两次） | 升格市场行动项 |
| 单条 + 明显项目个性 | 路由：报告给出建议写入该项目约定记忆文件的条目，人工回写 |
| 单条 + 疑似通用 | 留观：打标 `→ 留观 YYYY-MM-DD`，下次再现自然凑满门槛 |

项目个性判定线索：信号只在该项目台账出现、内容绑定该项目目录结构或历史欠债（如"存量静态类不再新增"类既定约定）。

## 真机样本入档

产物有跨项目示范价值时（新形态首次落地、纠偏前后对照），行动项类型为"样本进 examples"：脱敏（去业务敏感字段名、内网 host / IP）、带上下文说明（来源项目、触发信号、当时的拍板）。
