# 市场蒸馏巡检（慢环）

把散落在各消费项目台账里的生成信号，蒸馏成市场仓库的 skill 改进。本 skill 是慢环的唯一入口：**纯手动触发、无自动化、不考古会话**，台账（codegen ledger）是唯一信号输入。

## 输入

1. `references/consumers.md`：消费项目注册表（人工维护；路径失效或无台账的项目记入报告后跳过，不代建）
2. 各项目 `docs/codegen-ledger.md`：只取**行尾无处理标记**的条目
3. 市场仓库 `git log --oneline -15`：已回流规则，防重复蒸馏

## 工作流

0. **读注册表**：确认消费项目清单与路径存在性
1. **收集信号**：逐项目读台账未处理条目，汇总信号池
2. **归因分层**（每条信号先定层，再谈改动；判定细则见 `references/signals-and-thresholds.md`）：

   | 层 | 含义 |
   |---|---|
   | api-spec 层 | spec-to-model / spec-to-api 转换规则问题 |
   | UI 生成层 | wd-comp / ep-comp 生成规则问题 |
   | 装配接缝 | model/api 产物 ↔ UI 生成的引用形态、字段对不上——先判误差源头在上游还是下游，**改产生误差的一层** |
   | 非生成问题 | 后端 bug、环境、业务决策 → 报告说明，不入行动项 |

3. **分组过门槛**：同插件 + 同规则点聚合——复现 ≥2 条（跨项目或同项目两次）→ 升格市场行动项；单条 + 项目个性 → 路由报告（给出建议写入该项目约定记忆文件的条目，人工回写，本 skill 不代写）；单条 + 疑似通用 → 留观
4. **四分类行动项**：
   - **冲突改**：新信号与现有规则冲突 → **替换**旧规则，不并排堆叠
   - **缺失增**：规则缺口 → 增补，细则优先进 references/，SKILL.md 只动流程层
   - **冗余删**：规则被证伪 / 已被项目约定覆盖 → 删除
   - **样本进 examples**：真机产物有跨项目示范价值 → 脱敏存档（去内网 host、业务敏感字段）
5. **落点**：流程性规则 → SKILL.md；细则 → references/（单 reference.md 插件即该文件）；真机样本 → examples/
6. **执行改动**：前置检查（工作树、在途分支）与禁区见 `references/modify-discipline.md`
7. **打标**（对消费项目的唯一写动作）：行动项覆盖的台账条目行尾追加 `→ 已蒸馏 YYYY-MM-DD <plugin>@<ver>`；留观条目追加 `→ 留观 YYYY-MM-DD`（再出现时新条目无标，两条例目即凑满门槛）。台账原文永不改写
8. **报告**：写市场仓库 `.scratch/evolution-<日期>.md`（不进 git）——信号池、归因结果、门槛过滤详情、行动项与落点、待人工事项（merge + bump 建议、待回写项目约定清单、路径失效项目）

## Success Criteria

- 只处理台账未标记条目，无重复行动项
- 每个行动项带归因层与证据条目（≥2 条或留观说明）
- 未达门槛的信号没有直接进市场文件
- 消费项目侧只有台账行尾打标，无其他写入
- 改动在 `skill-evolution/<日期>` 分支，未 push，在途最多一个
- 报告给出 bump 建议（涉事插件 + 目标版本号）

## 不做的事

- 不考古跨会话对话 / diff（口径仅限台账内显式信号）
- 不 push、不 merge、不直接改 main
- 不创建 / 修改 / 删除任何自动化
- 不代写消费项目约定记忆文件与业务代码
- 不因单项目个性改动市场规则
- 不改插件版本号（bump 属于人工 merge 时）
