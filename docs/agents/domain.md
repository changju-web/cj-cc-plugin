# Domain Docs

工程类 skill 探索本仓库时应如何消费领域文档。

## 探索前先读

- 仓库根目录的 **`CONTEXT.md`**
- **`docs/adr/`** —— 读与即将工作的区域相关的 ADR

这些文件不存在时**静默继续**：不提示缺失、不建议预先创建。`/domain-modeling` skill（经 `/grill-with-docs`、`/improve-codebase-architecture` 触达）会在术语或决策真正敲定时懒创建它们。

## 文件结构（本仓库：单上下文）

```
/
├── CONTEXT.md
└── docs/adr/
    ├── 0001-xxx.md
    └── 0002-xxx.md
```

## 使用词汇表的词汇

输出中命名领域概念（工单标题、重构提案、假设、测试名）时，使用 `CONTEXT.md` 定义的术语，不要漂移到词汇表明确回避的同义词。

需要的概念不在词汇表里，这本身是个信号——要么你在发明项目不用的语言（重新考虑用词），要么存在真实缺口（记下来交给 `/domain-modeling`）。

## 标记 ADR 冲突

输出与现有 ADR 矛盾时显式指出，不要静默覆盖：

> _与 ADR-0007（xxx）矛盾——但值得重开，因为……_
